# Running a multi-page extraction (the Design System → `docs/DESIGN.md` sync)

Learned on the full Design System extraction (52 pages, 8 sections, a dozen runs). One lead session orchestrates; each run is one `dcl-designer-specialist` invocation.

- **Structure first, with the MCP; values with the browser.** Before any run, harvest `get_metadata` per page (densest pages first, calls ≥10 s apart) and save each XML to a file the runs read; stop at the first limit error. Everything else is the Properties-panel procedure in [`browser-extraction.md`](browser-extraction.md).
- **One run per Figma section, ≤5 pages or ~1 hour.** Split a dense section (Surfaces, Inputs) in two. The model for each run is the architect's call (`.claude/agents/dcl-ch-feature-architect.md`, the model paragraph).
- **Every run** reads `docs/DESIGN.md` first and copies its structure: the doc follows Figma's order, and its "Sections index" maps each Figma page to its section and set blocks. Each Figma section is a `##` with a "<Section> tokens" table, then one block per component set headed `### <Figma set name> (<page>)`: a header line (set link, variants with node ids, size, read date, a `Code: main` or `Code: ships in #<PR>` field), one value table with the ✱ rows, then the **Decisions** rows (current rules, no dates); tables only, no prose; verifies variant counts against the Layers tree; computes every contrast with [`../scripts/wcag.mjs`](../scripts/wcag.mjs) (it expands 3-digit hex); **persists readings to a notes file after each set**, so a usage-limit stop costs a relaunch, not the work — a stopped run resumes from its notes and never re-reads; ends in one checkpoint commit of `docs/DESIGN.md` only (`git add -- docs/DESIGN.md && git commit --no-verify …`, because the pre-commit hook rewrites and stages the whole tree); does not push; and reports cost (minutes, panel reads vs canvas measurements, confidence) plus findings split into **Figma-side defects (for design)** and **code-side decisions (for the user)**.
- **Token values never change in an extraction run.** Proposed tokens and values go in the handoff as PROPOSED; names are the user's call; value changes ship in their own PR with before/after shots of every `rg -l "var(--<token>)"` consumer.
- **The lead** pushes after each checkpoint and keeps every agent alive until its unit's Validate passes: TaskStop is final, and a stopped teammate can't be resumed. It switches branches only while no agent holds the tree, keeps one decision list, and asks the user once — after the runs — not per run. How to message, monitor and verify teammates is the architect's "Teammates" block (`.claude/agents/dcl-ch-feature-architect.md`), which governs where this differs.
